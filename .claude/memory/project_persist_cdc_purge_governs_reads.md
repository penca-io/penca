CHA-444 lifecycle redesign, converged with the user 2026-06-20, **implemented** 2026-06-21, **merged 2026-06-23 (PR #266, Linear auto-closed to Done).** **Supersedes** the earlier "split-grace / two-watermark / deferred hot-delete" framing — that was rejected in design review; the `nhobin219/cha-444-...` branch was reset to `origin/main` and re-implemented from the corrected design below, and ADR 0027 was rewritten to match (see the resolution at the bottom + the CHA-444 Linear resume checkpoint).

- **Persist = pure CDC**, committed-only, "nothing intelligent": committed ⇒ persistable to cold. **No open-tx clamp** — the `tx_seq_num` axis ([[project_mut_seq_num_sequence]], CHA-428/443) obsoletes it: commits get a strictly-monotonic seq *at commit*, so "persist all seq ≤ max-committed-seq" can never strand a late straggler (the micros clamp only ever absorbed out-of-order wall-clock commits). Persist races ahead of snapshot/purge ⇒ **P > W_snap essentially always**. Its cadence is never tied to snapshots — it's the CDC that shrinks the eventual-consistency window.
- **Reads are governed by `Pu` (the purge watermark), NOT persist.** Read model: `snapshot ≤ W_snap | cold-persist-log (W_snap, Pu] | hot (Pu, as_of]`. Happy path `Pu = W_snap` ⇒ hot serves `(W_snap, as_of]`, swallowing the persisted-but-unpurged band `(W_snap, P]`. So **hot serves persisted rows as steady state** — persisting does NOT evict a row from hot-read service; only Purge does.
- **Purge = clear-from-hot**, atomic, bounded `Pu ≤ P − grace`; `purged_at` = the clear point. **No** separate hot-purge-grace deferral / no two-watermark fence-vs-delete split. PG MVCC over early-materialized hot reads keeps in-flight reads safe, so the grace is only the upper bound on `Pu` (can be tight, ~1 min).
- **Purge owns aborts** — reverse ADR 0021's "Purge MUST NOT read `abort_tx_log`" non-goal. Forced by Persist→CDC: Persist is committed-only so it can no longer clean aborted hot rows; Purge must.
- **tx_log GC trails the PURGE watermark, not persist.** A persisted-but-unpurged tx is still live in hot and hot rows join `tx_log` for visibility; GC at min(persisted) would yank `tx_log` out from under live `(W_snap, P]` hot reads. GC at **min(purge) across the branch** (+ tx_table_log membership, as today) is safe — once purged, rows serve only from snapshot/cold, which carry pre-joined tx metadata (ADR 0017). **Persist-watermark gates durability; purge-watermark gates tx_log GC.**

**Open questions — RESOLVED + IMPLEMENTED (2026-06-21).** ADR 0027 rewritten; branch reset to origin/main and re-implemented (commits `f981dba9`, `8b9f9368`; `cargo check` clean, rust unit tests pass).
- Q1: `purged_at_micros` **dropped** — `table_purge_metadata` is seq-only (`last_purged_tx_seq_num`=Pu, `last_purged_aborted_seq_num`=Pa); `table_purge_uuid` seeds on `(Pu,Pa)`. tx_log GC re-axised to seq (all four family tables are seq-addressable).
- Q2: open-tx clamp **dissolves** (no replacement — seq axis makes it unnecessary for committed; aborts are invisible + terminal). Aborts are a **fully independent axis**: dedicated **gapless locked `abort_seq_num` counter** (mirrors `tx_log_seq_num`, NOT a commit-frontier sample — a sample stalls between commits and breaks Pa monotonicity) → `aborted_at_seq_num` → eager cleanup to frontier `F` → `Pa` watermark. NOT bounded at Pu (would strand commit-idle/pure-abort tables). `began_at_seq_num` stays a commit-frontier sample (it's the OpenTx read-isolation bound vs commit `tx_seq_num`; not a cleanup watermark).
- Q3 + a late design change: Purge cleans the **union** `abort_tx_log ∪ (begin_tx_log WHERE expired, no commit/abort)` — closes the expired-begin leak in-ticket, **superseding the CHA-467 reaper** (Canceled). Expired-begin *ledger* GC uses a **wall-clock expiry grace** (`expires_at < cleanup_started − query_timeout`), not Pa — expiry has no monotone seq.
- **Shipped (PR #266, merged 2026-06-23):** integration-test migration done, full `just check` green. Bugs fixed during impl: DeleteCatalog must drop the `abort_seq_num` parent; no-op Purge must not advance `Pa` from None when frontier==0. **Read-correctness fix landed late:** OpenTx cold isolation bound moved to the *read* side (`ReadSnapshot::plan_commit_seq_upper` → `began_at_seq_num - 1`) after the write-time `oldest_open_began_at` clamp was dropped — without it cold served rows committed *after* an open tx began. Also `compose_resolved` anti-joins cold against hot-shadowed `row_uuid`s. Post-merge cleanup: `PurgeTxLogResponse.purged_at_micros` removed (empty message — pre-release break, fine).
- **Persist's `effective_target` stays MICROS by design** (wall-clock drain "persist committed ≤ now", scheduler-driven), NOT a fence. Safe because `committed_at_micros` is stamped with `clock_timestamp()` *under the seq-counter row lock* (`penca-storage-hot/src/tx.rs::tx_log_insert_sql`), so it's **monotonic-non-decreasing with `tx_seq_num`** (the `now()` default would invert under concurrency — "the bug RT2 catches"). ⇒ a micros window is always a seq-contiguous prefix; no seq gap. Persisted segments carry `max_committed_tx_seq_num`; reads/GC fence on seq. Axis split: micros = open-tx TTL expiry (no seq for a never-committed tx), persist drain target, as-of time-travel, long-cleanup-race as-of pin; seq = every visibility fence + ordering.
